# show_git_brunch 插件設計

## 狀態與範圍

使用者已同意對話中的方案。本文件將方案固定為實作與驗收依據，等待文件確認後進入實作計畫。

在目前工作目錄新增 `show_git_brunch`，開發可安裝的獨立 DSH 插件。目錄保留使用者指定的 brunch 拼字。所有程式、測試、安裝設定與文件都位於此目錄；不修改既有插件或 DSH 核心，不自動提交、發布或安裝到使用者運行中的設定。

## 方案選擇

採用 DSH 原生對話頁頭部插槽與插件後端唯讀查詢。直接操作 DOM 容易因頁面結構變動而失效；替換整個頁頭則會影響其他插件，因此均不採用。

已從 DSH checkout 確認 `conversation.session.header.actions` 是有序的列表插槽，模式標籤的 order 為 -10。分支標籤使用其後的排序值（預定 -9），與模式在同一行顯示，不替換原有標籤。

## 顯示行為

- 僅在已進入對話的頁面頭部顯示 Git 分支圖示及分支名，例如 `main`。不提供切換分支或其他 Git 操作。
- 查詢目標為目前對話所屬的工作區目錄，而非 DSH 程序啟動目錄。
- 工作區位於 Git 倉庫子目錄時，顯示所屬倉庫的分支。支援 Git worktree，不假設 `.git` 必定是目錄。
- 尚無提交的倉庫仍顯示 symbolic HEAD 指向的分支。
- detached HEAD 顯示 `detached` 加短 commit ID，避免將其誤認為分支。
- 非 Git 工作區、工作區不存在、Git 不可用、權限不足、逾時或查詢失敗均隱藏標籤，不留佔位文字或空白容器。
- 長分支名截斷顯示，完整名稱透過 title 提示；分支名按文字渲染，不解析 HTML。

## 組件與資料流

1. 後端 Git 查詢模組只負責將可信任的工作區目錄轉成分支資訊或空結果。
2. 插件後端透過 DSH 支援的通訊介面接收對話識別資訊，從 DSH 的對話／工作區服務解析目錄。不得直接接受瀏覽器傳入的任意檔案系統路徑。具體服務及通訊 API 在實作計畫中以現有 DSH 程式為依據確認，不擅自新增核心介面。
3. 前端插件使用原生插槽取得目前對話上下文，呼叫後端查詢並顯示唯讀標籤。
4. 安裝包包括後端入口、可供 DSH 載入的前端產物及 bundle patch，README 說明建置、安裝、啟用與重載方式。

## 更新與生命週期

- 掛載、切換對話或工作區時立即查詢；切換時先清除上一個工作區的資訊。
- 頁面可見期間每 5 秒查詢，重新取得焦點或由隱藏轉為可見時立即更新。
- 頁面隱藏時不啟動定期查詢；避免同一元件的查詢重疊。
- 對話切換後忽略過期請求結果；查詢失敗清除旧標籤，不持續展示過期分支。
- 卸載時清理計時器與事件监听，忽略已發出的請求結果。

## 安全與錯誤處理

Git 命令以固定參數陣列執行，不使用 shell 拼接。只執行唯讀命令，限制執行時間與輸出大小，不改動 Git 設定、索引或工作目錄。後端遵循 DSH 既有對話／工作區存取規則。錯誤不向頁面洩漏本機路徑或原始命令輸出，也不影響對話功能。

## 驗證與驗收

- Git 模組：一般分支、中文或含斜線分支、未提交倉庫、detached HEAD、倉庫子目錄、worktree、非 Git 目錄、不存在目錄與執行失敗。
- 後端：依對話解析正確工作區、拒絕任意路徑查詢、空結果與錯誤行為。
- 前端：排序在模式之後、空結果不渲染、更新時機、隱藏暫停、卸載清理、切換時清除舊狀態與過期回應不覆蓋新狀態。
- 打包：確認 package 與 patch 引用的入口及前端產物存在，執行測試、語法／型別檢查及適用的建置檢查。
- GUI：若獲准安裝，於現有 `http://127.0.0.1:3080` 刷新後確認顯示與非 Git 隱藏，不啟動替代服務。沒有完成實際瀏覽器驗證時，明確列為未驗證，不以單元測試取代。

## 非目標

不顯示 dirty 狀態、ahead/behind、遠端分支或完整 Git 面板；不新增設定頁、不實作分支切換、不擴大修改範圍。
